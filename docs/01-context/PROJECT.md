## 2. プロジェクトビジョン

### ミッションステートメント

東京都オープンデータカタログの約9,600データセットを、訪日観光客の「旅の相棒」に変える。「1データ＝1アプリ」という活用の型を終わらせ、アプリが作られていないデータにも会話から到達できる入口をつくる。

### ビジネス価値

- **旅行者**: 出典付きの旅程・文化マナー・地域情報を、探索時間 約30分 → 約3分で得られる
- **地域**: 有名観光地への集中を緩和し、地域の店・街へ送客する（観光の分散）
- **東京都 / GovTech東京**: 「聞かれたのに答えられなかった」欠損をデータ公開リクエストとして還元し、オープンデータ政策の改善センサーとして機能する
- **翌年のハッカソン参加者**: バックエンドは MCP サーバーとして開放され、旅行アプリは「最初のクライアント」にすぎない

### 成功指標

- 回答成功率（出典付きで回答できた質問の割合）
- 出典クリック率（東京都オープンデータカタログへの流入）
- 地域スポット送客数
- データ公開リクエスト数（未回答ログから生成された都への提案件数）

## 4. 要件定義

### 機能要件

#### コア機能

フロントエンド「旅コンシェルジュTOKYO」の5機能。

> **UI の実態（2026-08-15 訂正）**: 完成しているのは**デザインプロトタイプ**（`public/showcase/` → `/showcase/`）であり、API を叩ける React アプリではない。実装は `src/` で新規に進めており、プラン画面から着手する。

> チェックの基準は**オープンデータ接続まで完了したか**。UI 単体の実装は完了しているが、実データとの接続が未了のため未チェックとしている。進捗の追跡は [TASKS.md](../07-project-management/TASKS.md) を SSOT とする。

- [ ] 👤 旅のプロフィール: 同行者・興味・ペースを入力し、パーソナライズ条件をコンテキストとして送信する
- [ ] 🗺️ プラン: オープンデータからAI旅程を生成し、マナー解説を添える（出典リンク必須）
- [ ] 📷 スキャン: カメラ画像からAI文化ガイドを提示する（鳥居の作法等）
- [ ] 📍 周辺: 地域ガイド（住民ルール・お知らせ）を提示し、データ欠損を検知する
- [ ] ✨ あなたへ: 興味ベースのスポット推薦（オープンデータ由来・出典付き）
- [ ] 出典強制: 全回答にデータセットへのリンクを構造的に付与し、根拠がなければ「ありません」と答える
- [ ] MCP 接続: フロントエンドがバックエンドの最小3ツール（データセット検索・集計・出典取得）を呼び出す

#### 拡張機能

- [ ] データ公開リクエスト: 未回答ログを分類し、都への公開・更新優先度提案に変換する
- [ ] 「オープンデータあるべき姿レポート」の四半期自動生成
- [ ] 多言語対応（デザインプロトタイプは日英2バージョンあり。実装は未着手。やさしい日本語へ展開可能）
- [ ] 介助者モード・音声対応（Final Stage 構想）
- [ ] MCP サーバーの外部公開（翌年参加者への基盤開放）

### 非機能要件

#### パフォーマンス

- レスポンスタイム: 未定（POC 実装時に実測して設定。プレゼンで訴求する「探索 30分 → 3分」は体験全体の指標であり、単一応答の SLA ではない）
- 同時接続数: 未定（First Stage はライブデモ不可のため、収録時点では負荷要件なし）
- データ処理量: POC では利用オープンデータ最大10件をダウンロードしてアプリに同梱する範囲に限定

#### セキュリティ

- 認証方式: 未定（POC では利用者認証を伴う機能を実装しない方針。Final Stage で要判断）
- 認可レベル: 未定（同上）
- データ暗号化: 取り扱うのは公開済みオープンデータのみ。個人を特定する情報は保持しない

#### 可用性

- SLA: 未定（ハッカソン提出物のため SLA 契約は存在しない）
- バックアップ: 未定（同梱データは Git 管理下に置く方針）
- 災害復旧: 該当なし（本フェーズでは対象外）

## 5. スコープ定義

### 含まれるもの

- オープンデータをダウンロードしてアプリに組み込む POC 実証
- 渋谷・上野など代表エリアに絞った画面イメージ
- 代表シナリオ（渋谷ナイトライフ・上野ファミリー）の縦貫通（データ → 旅程 → 出典）
- MCP 接続の POC（最小3ツールの呼び出し）
- モック（静止画＋カーソル操作）でも成立するデモ動画

### 含まれないもの

- 約9,600件全件の動的取り込み
- 全都域対応のフル実装
- 動的なバックエンド更新の仕組み（Final Stage 以降の構想として提示）
- ライブデモ（First Stage では規定上不可）
- フルツールセット／複数クライアント同時対応（Final Stage 構想）

## 8. 成功基準

### 定量的指標

- 回答成功率: 目標値は未定（POC で初期値を実測してから設定）
- 出典付与率: 100%（設計上の必達要件。根拠がなければ回答を生成しない）
- 情報探索時間: 約30分 → 約3分（提出までに実測で更新）

### 定性的指標

- 全提案に東京都オープンデータカタログへの出典リンクが付き、CC BY 4.0 の表示義務がアーキテクチャレベルで自動的に満たされていること
- 未回答 → データ公開リクエスト → データ増加 → 回答範囲拡大、の自己改善ループが資料上で説明できること
- バックエンドが MCP サーバーとして独立し、旅行アプリ以外のクライアントからも利用可能な形になっていること
