### ACE-4-1: 配置済みファイルを「必要時にコピー」と案内し続ける索引は、次の実行で自分の修正を消す経路になる

| Category | knowledge-management | Origin | PR #4 |
| Date | 2026-08-15 |
| Helpful | 0 | Harmful | 0 |
| Status | active |

テンプレート集からファイルを配置したとき、それを列挙している索引（DEPLOYMENT.md 等）が「未導入なのでコピーせよ」と案内したままだと、後続のセッションがその指示に従って原文を上書きし、配置時に加えた修正が黙って消える。配置と索引更新は必ず同じ PR で行い、索引側に「配置済み・コピー不要」を明示する。テンプレート由来ファイルを追加したら、そのファイルを指す索引を全て grep して状態を揃えること。

### ACE-8-2: チーム外の人が入る瞬間、個人設定に置いたルールは「緩い」のではなく「存在しない」

| Category | knowledge-management | Origin | PR #8 |
| Date | 2026-08-15 |
| Helpful | 0 | Harmful | 0 |
| Status | active |

グローバル設定（`~/.claude/CLAUDE.md`）やローカル導入プラグインに書いた運用ルールは、自分の全プロジェクトに効く代わりに他人には1文字も届かない。外部メンバーが参加した時点で、彼らにとっての実効ルールはゼロになる（「手順が重い」という相談の裏に、この構造が隠れていることがある）。個人設定は「自分がどう働くか」、リポジトリ内の `CLAUDE.md` / `AGENTS.md` / `CONTRIBUTING.md` は「このコードベースがどう扱われるべきか」として最初から分けて置く。
