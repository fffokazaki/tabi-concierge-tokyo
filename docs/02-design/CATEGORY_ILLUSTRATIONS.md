# カテゴリイラスト設計

## 1. 目的と対象

[Issue #188](https://github.com/fffokazaki/tabi-concierge-tokyo/issues/188) に基づき、プラン画面の停留地カードに、場所そのものではなく**分類を示す抽象イラスト**を表示する。写真や実在の外観を描かず、オープンデータ由来の事実と誤読されない補助表現に限定する。

対象は `src/features/plan/` の `.stop-card__thumb` のみ。「あなたへ」画面、写真、地図サムネイルは対象外とする。

## 2. 採用する視覚方針

- 基調: 深い藍色の太い手描き線と、淡い砂色・杏色の色面
- 形: 52×52px でも判別できる単純な輪郭と十分な余白
- 背景: 現行 UI と馴染む温かいアイボリー
- 未知カテゴリ: 空の角丸枠の右下に、小さな杏色の四点印と藍色の点
- 禁止: 写真、実在施設の外観、寺社・鳥居・墓・絵巻など特定の地物を示す絵、文字、ロゴ

2026-08-22 に `imagegen` で比較した3方向のうち「藍の一筆線」を採用し、
未知カテゴリだけ「やわらかな紙版画」案の空枠表現を組み合わせる。

## 3. カテゴリ写像

`data/` の2026-08-16スナップショットを `scripts/seed.ts` と同じ列選択規則で集計した結果、施設行は1,645行・16カテゴリである。各グループの絵は個別施設ではなく、右表の分類だけを表す。

`culture` と `heritage` は対象行の形を描かない。「観光」には観光案内、資料館、図書館、文化会館、動物園などが混在し、「名所・史跡」には寺社、墓、碑、像、建物が混在するためである。分類用の抽象印なら、どの行についても特定の外観や物体を主張しない。

## 4. データ契約と表示分岐

### 4.1 データフロー

1. D1 の `spots.category` を Text-to-SQL の選択行に必ず含める
2. `AggregateResult` を `{ name, summary, category }` とする
3. LLM・D1障害時の固定サンプルにも、原本CSVで照合した `category` を持たせる
4. プラン画面の応答検査で、`category` が非空文字列であることを検査する
5. `Stop.category` へ写し、`RouteStopCard` が完全一致の写像を解決する

データセット名からカテゴリを推測しない。1データセット内に複数カテゴリがあるため、実際に選ばれたD1行の値を運ぶ。

### 4.2 表示状態

| 状態 | 表示 | 理由 |
| --- | --- | --- |
| 16カテゴリの写像に一致 | 対応グループのイラスト | 全行監査済みの分類表現 |
| 非空だが写像にない将来のカテゴリ | 空枠＋小さな印 | 他カテゴリの絵で代替しない |
| 既知カテゴリを意図的に未割当にした場合 | 従来の無地グレー | 安全な絵が無い状態を隠さない |
| API の `category` が欠落・空 | 仕様外応答として既存の `parse` 障害 | API破損を「未分類」に見せて隠さない |

未知カテゴリ用イラストは「データに画像が無い」ことを表す装飾であり、オープンデータの出典ではない。`alt` は空にし、既存の出典チップと同じアクセント色・下線・ラベルを使わない。

## 5. 資産管理

- 各グループと未知カテゴリを**別々の画像**として `imagegen` で生成する。コンタクトシートを切り出して最終資産にしない
- 元画像は正方形で生成し、表示用は縦横比を保ったままブラウザ向け形式へ変換する
- 同じ藍色線、背景、余白、線幅を全資産で固定する
- `src/assets/category-illustrations/` に配置し、Vite のアセットパイプラインでハッシュ付き配信する
- 生成手段は「OpenAI imagegen（Codex built-in。
  基盤モデル名はツールから開示されない）」と正確に記録し、
  推測したモデル名を書かない
- 画像はオープンデータ由来ではなく、アプリの分類補助用に生成した作品であることを本書に記録する

## 6. テストと検証

- 原本CSVを `scripts/seed.ts` と同じ規則で読み、16カテゴリと行数が本書の表から変わっていないことをテストする
- Text-to-SQL主経路と固定サンプル縮退の両方が、非空の `category` を返すことをテストする
- プラン画面の応答検査が `category` の欠落・空を `parse` 障害にすることをテストする
- `RouteStopCard` で、既知カテゴリ・未知カテゴリ・既知未割当の3表示を固定する
- 52×52px、通常・選択・ドラッグオーバー状態で、画像と出典チップが競合しないことをブラウザで確認する
- `npm run typecheck`、`npm test`、`npm run build`、文書検証を通す

## 7. リリース境界

`worker/` と `shared/` のAPI契約を変更するため、`develop` へのマージだけでは
完了としない。[DEPLOYMENT.md](../05-operations/DEPLOYMENT.md) に従って手動デプロイし、
本番URLで次を確認する。

1. 既知カテゴリの停留地に対応イラストが出る
2. 出典チップと施設名・説明が従来どおり表示される
3. API応答に実在する `category` が含まれる
4. スライド6の既存キャプチャは見た目が変わるため、提出資料で差し替え要否を再判定する
