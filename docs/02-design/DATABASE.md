# DATABASE.md - データベース設計書

> **本プロジェクトはデータベースを使用しない。** POC（2026-08-15 合意）では、東京都オープンデータカタログから**ダウンロードしたデータをアプリに同梱**する方式を採る。本書はその判断と、代わりに管理すべきデータ資産の一覧を記録する。RDBMS を導入する場合は本書をテンプレートに戻して設計し直すこと。

## 1. データベース概要

### データベース構成

- **RDBMS / NoSQL**: 使用しない
- **理由**: 2日間のハッカソンスコープでは永続化要件が発生しない。約9,600件の動的取り込みを行わず、提出対象の最大10データセットを静的ファイルとして同梱する（[ARCHITECTURE.md](./ARCHITECTURE.md) §4、ADR-004）
- **将来**: Final Stage で動的取り込みへ移行する場合、メタデータ索引の保持先としてデータストアの要否を再評価する

## 2. データ資産（データベースの代替）

### データの持ち方

```
data/          # 利用オープンデータの実体（CSV / GIS）とメタ情報
  └ <dataset-id>/   # カタログのデータセットIDで管理し、出典URLと1:1に対応させる
```

- 各データセットは**カタログの URL・タイトル・取得日**をメタ情報として必ず持つ。これが出典強制（[ARCHITECTURE.md](./ARCHITECTURE.md) §1）の実データ源になる
- ライセンスは CC BY 4.0。出典表示義務の詳細は [CONSTRAINTS.md](../01-context/CONSTRAINTS.md) §3

### 既知のデータ欠損（2026-08-15 調査）

- 観光地・神社など有名スポットはデータが揃う一方、**小規模店舗（小さなラーメン屋等）はオープンデータ未カバー**
- この欠損は隠さず、「データ公開リクエスト」として都へ還元する仕組みの題材にする（[DOMAIN.md](./DOMAIN.md) §7）

## 3. データ品質と更新

### 更新頻度への対応

| データ | 更新頻度 | 対応 |
| ------ | -------- | ---- |
| 東京都の人口（推計） | 毎月 | 提出直前に最新月の URL へ差し替える |
| その他 | 不定期 | 取得日をメタ情報に記録し、資料に反映する |

### 整合性の考え方

- POC のデータはダウンロード時点のスナップショット。回答には**出典 URL と取得日**を添え、利用者がカタログの最新版へ辿れるようにする
- 同梱データとカタログ最新版の差異は「劣化」ではなく明示すべき事実として扱う

## 4. バックアップ・リカバリ

- 同梱データは Git リポジトリで管理し、リポジトリのバックアップをもって代替とする
- 個別のバックアップ運用は行わない（本フェーズでは対象外）

## 5. セキュリティ

- 取り扱うのは公開済みオープンデータのみ。秘匿情報・個人情報は保持しない
- アクセス制御・暗号化の要件は現時点で該当なし（[CONSTRAINTS.md](../01-context/CONSTRAINTS.md) §5）
