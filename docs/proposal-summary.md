# 企画概要｜旅コンシェルジュTOKYO v1.0

## 課題

- 東京都オープンデータカタログには約**9,600データセット**が公開されている一方、カタログの利用は**1日約200PV**
- 原因は「**1データ＝1アプリ**」という活用の型。誰かがアプリを作ったデータしか届かない
- 訪日観光客は文化・マナーの壁に直面しても、公共データにアクセスする手段がない

## 提案

訪日観光客向けAI旅行ガイド「旅コンシェルジュTOKYO」。

### 5機能（UI実装済み）

| 画面 | 機能 |
| --- | --- |
| 👤 旅のプロフィール | 同行者・興味・ペースを入力 |
| 🗺️ プラン | AI旅程生成＋マナー案内 |
| 📷 スキャン | カメラでAI文化ガイド |
| 📍 周辺 | 地域住民の投稿・お知らせ |
| ✨ あなたへ | 興味ベースの推薦 |

### アーキテクチャ

- フロントエンド（React）↔ **MCP** ↔ オープンデータ・コンシェルジュ
- MCP最小3ツール: データセット検索・集計・出典取得
- バックエンド: メタデータRAG＋Text-to-SQL＋出典強制（OpenCode＋Cloudflare）

### 独自性

1. **出典100%**: 全回答にデータセットリンクを強制付与。CC BY 4.0の表示義務を設計で自動達成
2. **データを育てる**: 答えられなかった質問をデータ公開リクエストとして都へ自動還元（改善センサー）
3. **基盤の開放**: コンシェルジュはMCPサーバー。旅行アプリは“最初のクライアント”にすぎず、翌年の参加者に開放

## インパクト / KPI

- 情報探索時間: 30分 → 3分
- 観光分散（有名地集中の緩和→地域の店・街へ送客）
- KPI: 回答成功率／出典クリック率／地域スポット送客数／データ公開リクエスト数

## キーメッセージ

> 公開されていても、届かなければ、開かれていない。
> 「1データ＝1アプリ」の時代を、旅から終わらせる。
