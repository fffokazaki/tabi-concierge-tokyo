# 企画概要｜旅コンシェルジュTOKYO v1.1

> **9,600のオープンデータを、旅の相棒に。**
> 訪日観光客向けAI旅行ガイド。その頭脳として、後ろにオープンデータ・コンシェルジュ（MCPサーバー）が静かに控える。

## 課題

- 訪日観光客は文化・マナー・地域情報の壁に直面するが、都の公共データにアクセスする手段がない
- 東京都には約**9,600データセット**が公開済み。一方カタログの閲覧は**1日約200PV**
- 原因は「**1データ＝1アプリ**」という活用の型。アプリが作られたデータしか誰にも届かない

## 提案：旅コンシェルジュTOKYO

旅のプロフィールを入れると、旅程とマナーを提案。カメラをかざせば文化を解説。地域住民の声も届く。**すべての提案に出典（オープンデータ）が付く。**

### 5機能（UI実装済み）

| 画面 | 機能 |
| --- | --- |
| 👤 旅のプロフィール | 同行者・興味・ペースを入力 |
| 🗺️ プラン | AI旅程生成＋マナー案内 |
| 📷 スキャン | カメラでAI文化ガイド |
| 📍 周辺 | 地域住民の投稿・お知らせ |
| ✨ あなたへ | 興味ベースの推薦 |

### 体験フロー（例：「明日は浅草と上野。ラーメンが好き。」）

1. 旅行者がプロフィールと行きたい場所を入力
2. オープンデータから旅程を生成（出典リンク付き）
3. 神社の参拝作法など文化・マナーを先回りで案内
4. データにない小さな店は「データ公開リクエスト」として都へ自動還元

## 後ろで支える仕組み（要点のみ）

- バックエンド「オープンデータ・コンシェルジュ」＝メタデータRAG＋Text-to-SQL＋出典強制
- アプリとは**MCP**で接続。旅行アプリは“最初のクライアント”にすぎず、基盤は翌年の参加者に開放
- CC BY 4.0の出典表示義務を設計で自動達成。主役は旅体験であり、コンシェルジュは黒子に徹する

## インパクト / KPI

- 旅行者の探索時間: 30分 → 3分
- 観光の分散で地域へ、利用ログの還元で都政へ価値を返す
- KPI: 回答成功率／出典クリック率／地域スポット送客数／データ公開リクエスト数

## キーメッセージ

> 公開されていても、届かなければ、開かれていない。
> 「1データ＝1アプリ」の時代を、旅から終わらせる。
