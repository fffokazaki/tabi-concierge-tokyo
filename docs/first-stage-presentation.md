## ナレーション台本（約620字＝2分）

1. （0:00–0:12）東京都には約9,600ものオープンデータがあります。私たちはこれを“旅の相棒”に変えました。旅コンシェルジュTOKYOです。
2. （0:12–0:30）9,600のデータセットが公開されている一方、カタログの閲覧は1日約200PV。原因は「1データ＝1アプリ」という活用の型です。アプリが作られたデータしか、誰にも届きません。
3. （0:30–0:50）そこで私たちは、訪日観光客向けのAIガイドを作りました。旅のプロフィールを入れると旅程とマナーを提案。カメラをかざせば文化を解説。地域住民の声も届きます。ご覧のとおり、UIは実装済みです。
4. （0:50–1:10）頭脳はバックエンドの「オープンデータ・コンシェルジュ」。メタデータRAGとText-to-SQLで9,600件から答えを組み立て、MCPでアプリに接続します。回答には出典を100%強制付与。CC BYの表示義務も設計で自動的に満たします。
5. （1:10–1:25）例えば「明日は浅草と上野、ラーメンが好き」。オープンデータから旅程を生成し、神社の作法まで先回りで案内。すべての提案に出典が付きます。
6. （1:25–1:40）答えられなかった質問は、データ公開リクエストとして都へ自動還元。使うほどオープンデータが育ちます。しかもMCPサーバーなので、このアプリは“最初のクライアント”にすぎません。基盤ごと翌年の参加者に開放します。
7. （1:40–1:52）旅行者の探索時間は30分から3分へ。観光の分散で地域にも、利用ログの還元で都政にも価値を返します。
8. （1:52–2:00）公開されていても、届かなければ、開かれていない。「1データ＝1アプリ」の時代を、旅から終わらせます。
